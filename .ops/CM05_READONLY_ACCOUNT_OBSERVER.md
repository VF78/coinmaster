# CM-05 read-only Hyperliquid account observer

2026-09-26 source-only pass on pinned Nautilus 1.231.0. No installed worker, service env, native strategy, execution route, order, wallet, signing key, approval seal, or deployment changed.

The new observer uses only the official mainnet Info URL with an allowlist of userRole, clearinghouseState, frontendOpenOrders, orderStatus and userFillsByTime requests. Its account_ref comes from the public master or subaccount address; an agent/API wallet is rejected by role, and no signing secret is accepted. The tracked Stage-G env example documents an optional public address setting for the existing root-owned /etc service env. It is intentionally not installed in that env while the current virtual BTC/TP worker must remain untouched. Official account-address and role contracts: https://hyperliquid.gitbook.io/hyperliquid-docs/for-developers/api/info-endpoint

The observer calls the existing strict conditional Info collector, validates the account value, owned open orders and positions, durable CLOID/OID order statuses, and bounded fill window. It exposes only a read model: observed account value/counts, connection and evidence state, age, and reason. A disconnect, malformed/partial reply, timeout, unverified role or stale read clears current account facts and yields UNKNOWN or RECOVERY_REQUIRED. A late in-flight read cannot undo a disconnect. A successful resync stays CONDITIONAL_ONLY with recovery_required=true, orders_enabled=false, retry_uncertain_orders=false and live_order_capability=false. The Info endpoints offer no common atomic cursor or proof against silent omission, so this does not authorize native takeover.

Fake transport validation: runtime/tests/test_hl_info_receipt.py plus runtime/tests/test_hl_readonly_observer.py, 24 passed. The public address previously identified by owner was read-only checked separately and had user role with zero account value/positions; this source-only test does not assert it owns any actual venue order or fill. Future native integration requires complete authoritative reports and an explicit ownership/recovery gate; uncertain submits may never be retried from this conditional observer alone.

One bounded source-only Info transport smoke used the owner-identified public master account reference through the new transport: role accepted, account value 0.0, zero open orders/positions/fills in the requested current-millisecond window, CONNECTED_INFO and CONDITIONAL_ONLY, with recovery_required=true, orders_enabled=false and live_order_capability=false. It did not query a wallet, sign, call /exchange, or claim a complete historical fill window. No worker or service state changed.
