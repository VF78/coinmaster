Genuine empty order/position/fill responses produce a conditional receipt only when the caller has no fill anchor; that receipt explicitly records fill_anchor_proven=false.

This is intentionally not an execution-client subclass or native report conversion. It neither calls a live endpoint nor writes native cache/domain, and never sets recovery_confirmed. A bounded response below the published cap is only conditional evidence: Info has no cross-endpoint atomic snapshot/cursor, no proof against silent omissions below cap, and its 10000-fill retention can outrun a durable checkpoint. Historical fill continuity and native account/order parity must still be established by a separately scoped native reconciliation path. The installed 1.231 bulk adapter remains unsuitable for takeover. Focused fake Info and existing recovery tests: 39 passed; no service or active worker action.
