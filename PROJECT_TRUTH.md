## Анти-залипание (обязательное)
- Если нет подтверждённого прогресса 10–15 минут → статус `blocked`.
- Если проблема воспроизводится → сначала минимальный reproducible case.
- После 2 неудачных попыток → стоп + гипотезы + что нужно от человека.

## Качество (обязательное)
- Порядок: diagnosis/explore → plan → implementation → verify.
- Перед статусом «готово» обязательно:
  - проверить запуск,
  - проверить ключевой сценарий,
  - зафиксировать риски.
- При изменениях infra/конфига всегда давать rollback-шаг.

## Чувствительные изменения (торговля/бот)
- Не менять торговую логику, risk-параметры и execution path без явного указания Владимира.
- Любые изменения стратегии сопровождаются:
  - гипотезой,
  - способом проверки (backtest/dry-run),
  - перечнем рисков.

## Heartbeat protocol
- Каждые 15 минут, пока работаю над задачей, отправляю короткий heartbeat формата `Heartbeat: <Status> | <Summary> | Next: <next action>`; отсутствие изменений за 10–15 минут переводит задачу в `blocked` и требует нового Claude Code кванта.
- Подтверждённый прогресс = изменение файлов, выполнение проверок или обновление статуса в GitHub Project.
- Перед сообщением о завершении задачи всегда выполняю тесты/проверки самостоятельно (минимум: `check` + `build` + релевантный smoke) и только после этого прошу Владимира проверить в проде.
