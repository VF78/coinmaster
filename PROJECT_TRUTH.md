## Анти-залипание (обязательное)

## Heartbeat protocol
- Каждые 30 минут, пока работаю над задачей, отправляю heartbeat в формате:
  `Heartbeat: • Done: ... • In progress: ... • Blockers: ... • ETA: ...`
- Если Claude Code не даёт подтверждённого прогресса >30 минут: отменяю текущий запуск, разбиваю задачу на мелкие подзадачи, обновляю checklist в issue/project и продолжаю последовательно.
- Подтверждённый прогресс = изменение файлов, выполнение проверок или обновление статуса в GitHub Project.
- Перед сообщением о завершении задачи всегда выполняю тесты/проверки самостоятельно (минимум: `check` + `build` + релевантный smoke) и только после этого прошу Владимира проверить в проде.
- В сессии включён автоматический reminder каждые 30 минут (`cron job: coinmaster-heartbeat-reminder-30m`) для соблюдения heartbeat-дисциплины.

## Anti-overload / anti-freeze policy (added 2026-03-01)
Причина инцидента: хост с 4 GB RAM входил в OOM, kernel убивал `openclaw-gateway` и `claude` процессы; в это время ассистент зависал/отвечал с задержкой, а сервисы могли временно деградировать.

Обязательные правила:
1. Не запускать параллельно несколько тяжёлых Claude/ACP раннов без подтверждённого артефакта от предыдущего.
2. При повторных `ACP_TURN_FAILED` не делать spawn-шторм: максимум 1 активный run, затем diagnosis/restart.
3. Агрессивные watchdog-ремайндеры (10м) включать только при стабильном хосте; по умолчанию — выключены.
4. Держать ограничение памяти для `openclaw-gateway` через systemd user drop-in (`MemoryHigh≈1.2G`, `MemoryMax≈1.7G`) и auto-restart.
5. Перед новым запуском Claude чистить зависшие `claude/claude-agent-acp` процессы.
6. Всегда проверять после инцидента: `uptime`, `free -h`, OOM-логи (`journalctl -k | grep -i oom`), `openclaw status --deep`, `coinmaster/nginx` status, `curl -I https://coinmaster24.com/`.
