## Ordered work and acceptance

1. **Read-only Runtime/Dashboard bridge.** Add a narrowly scoped, authenticated projection for the isolated HL Sandbox instance without giving the API ownership of Nautilus orders or access to its private writable DB. The trader offers only GET `/status` on IPv4 loopback port 18183; the sidecar applies a 15-second observation TTL and validates instance/capability. Show identity, candidate/code/policy hashes, dry-run mode, `live_order_capability=false`, fresh/warmup/feed gates, process status, positions/orders/events and verified account fields. Display explicit `UNKNOWN`/`UNPOSTED` where no observed value exists. Reuse Dashboard/History components. Test disconnected/stale/wrong-instance/empty/open states and prove it never reads the older paper instance as HL.
2. **Strategy page.** Show exact sealed Stage-G candidate as the running immutable version, research drafts separately, venue/currency and 10,000 USDC virtual-seed assumption. Correct the stale HL preflight copy and wire public margin previews only to real profile evidence. Saving a draft never changes the running strategy.
3. **Research/optimizer workspace.** Retain owned-process native BacktestEngine jobs and immutable artifacts. Add bounded staged optimizer job configuration and truthful progress/cancel; compare control/winner and TOP-20 by terminal TOTAL, with ACTIVE/RESERVE, ROI, maker/taker fees, funding, fills, liquidation count and DD. Block new runs when genuine source coverage is absent. Keep diagnostic results visibly non-faithful/non-live-ranking.
4. **Commands and deployment.** Add pause/resume/flatten only after a dedicated authenticated, idempotent HL Sandbox command channel and fail-closed tests exist. Deploy the SPA/API separately from the trader; verify authenticated access, stale/error states, no trader restart and no real-exchange execution capability. Domain/TLS work is a later operational step, not a prerequisite for local GUI adaptation.

Final production pass: remove unused migrated routes/components/API calls from the Nautilus bundle after checking imports and the separate legacy build; do not delete a component still used by either build. Verify desktop/mobile navigation and all empty/stale/error states against API fixtures and an authenticated deployed browser walkthrough. Every state-changing Sandbox action needs validation, idempotency, clear confirmation/loading/error feedback and read-after-write reconciliation; an HTTP acceptance is not proof of native state change. Deploy API/SPA separately from the trader and confirm process identity, rollback and unchanged Sandbox-only execution allowlist.

No Freqtrade package, JS PnL engine, exchange credential form, live-order action or new GUI stack is required. D5 natural virtual entry/exit/account evidence remains in progress and must not be manufactured by the GUI. The warmup artifact must be refreshed and revalidated at every UTC day boundary independently of this GUI work.
