## Five limitations that matter for the next dataset

1. **The sampling unit is an origin, not an independent event.** The full OOF has 8,496 origins with overlapping 72h targets and only 29 paired 14d blocks. A prolonged move can contribute multiple adjacent labels. The reviewed artifacts do not supply event IDs, recurrence counts, or the number of unique growth→correction/fall→rebound episodes. No exact duplicate-event or effective-sample-size count is defensible from these summaries. The 24 GPT cases avoid future-window overlap, while dependence through input/state remains. Highest-value change: establish causal event IDs and event-level sampling/evaluation before another encoder comparison.

2. **A fixed clock window can mix phases, but that explanation remains untested.** Continuous-window input may contain launch, trend, correction and recovery in changing proportions. No completed-event/prefix representation was tested in these artifacts. Spatial/flat failures narrow particular representations; they do not directly test phase-aligned event learning. Highest-value change: retain full chronological history and describe age, amplitude, duration, retracement and phase of a causal event, then compare event-aligned versus equal-information clock windows on the same decision origins. Do not replace the dataset with only retrospectively attractive completed patterns.

3. **State and shape are not cleanly identified.** Context-only, prior and numeric controls already exist, and one CNN-versus-context short-Q result is positive. Removing an image also changes capacity, and P−C changes numeric windows plus chart together. Four coarse trend/volatility regimes do not explain all drift: F3 common-support short-Q deterioration versus prior is +.014719, CI [.001685,.027355], and 485 late UP_HIGH origins are outside shared support. Highest-value change: compare event shape against matched origin-known state controls, separately report common and missing support, and preserve all regimes/months. A residual shape effect after state adjustment is a hypothesis, not an established cause.

4. **Directional classification and stop-conditioned opportunity answer different questions.** D is first ±1σ72 barrier/NONE; Q is MFE before a fixed stop, not direction accuracy, realized profit, or an optimal stop. The same 1/1 barriers give exact D/TP-before-SL label identity on all 8,496 unambiguous IDs, yet F1 short predictions violate their compatibility bounds 24.11% of the time; F3 only 1.75%, so incoherence does not explain all failure. Highest-value change: define event continuation/reversal/failure and competing barrier/time outcomes jointly, with censored/ambiguous cases retained. Evaluate proper losses for the declared task; never turn a 50% D accuracy into proof of useful TP/SL forecasts.

5. **Attainable excursion and touch are not executable trade outcomes.** For fixed CNN TPs, widening SL 1→1.5σ raises median TP-before-stop by only .38–3.95 percentage points across fold/side cells while raising stop distance about 50%. Full-horizon adverse touch differs from stopout after partial exits. Quantiles .2/.5/.8 correspond to separate approximate 80/50/20% target-hit rates, not 80% for the entire ladder. Highest-value change: first learn/validate event path risk and completion/censoring targets, then separately specify any finite trade policy, costs, sizing and execution semantics. Actual ROI/DD remain NOT_EVALUATED; native replay count is zero. Event labels alone cannot resolve economics.

## Strongest next hypothesis and falsifiable design

Hypothesis: causal phase alignment and event-level weighting improve prediction of what follows an observed growth/fall→correction prefix, beyond the same market-state information and a simple event-conditioned empirical prior. This targets dataset/targets/sampling first; it is not a request for another encoder grid.

Freeze one causal event state machine before outcomes are opened. A growth/fall event starts only when a rule using then-available prices crosses a predeclared volatility-scaled move threshold. An extremum and correction become observable only after a predeclared reversal/confirmation delay; preserve both extremum time and confirmation time. An event may be called complete in the training archive after completion, but its completed representation becomes eligible only after that confirmation and label maturity. Never place the decision origin at a future-known peak/trough or retrospectively trim the input to its eventual best boundaries.

For the proposed trading question, take the query at the first causally observed correction/rebound prefix, and predict the remaining path. Store the completed historical event as the eventual outcome of that same prefix, not as information available to the query. If the question instead starts after a fully confirmed growth→correction event, its target must be the subsequent path after confirmation; it cannot claim prediction of the correction already observed. These are distinct tasks and should not be pooled silently.

Retain every eligible event start: continuation without correction by deadline, failed reversal, truncated event, adverse barrier, and unresolved data-end cases. A not-yet-complete event at the observation cutoff is censored/at risk, not automatically a failure or discarded negative. Use a fixed maximum follow-up and explicit censor masks; keep interval bounds when minute ordering is unknown. Store event ID, start/confirmation/query times, prefix version, origin-known state, physical barriers, future endpoint, failure/censor reason and outcome-maturity time. These are proposed fields, not labels computed in this audit.

Freeze one primary query per event for the primary estimate. Additional prefixes may be useful secondary observations, but keep one event in one split and weight/cluster it as one event rather than multiplying its apparent evidence. Purge by actual input and future-outcome intervals, including confirmation dependencies; require matured historical examples at each query. Preserve the full DEVELOPMENT chronology, report all eligible starts and completion/failure/censor denominators by fold/state, and reserve any subsequently authorized fresh evaluation for genuine confirmation. Existing repeatedly reused DEVELOPMENT results remain exploratory; no power or fresh-CHECK claim follows.

Use the same eligible query IDs to compare: (a) full-prefix empirical prior, (b) causal state-only model/prior, (c) event descriptors and shape plus that identical state, (d) equal-information fixed clock-window representation. Freeze simple matched-state strata using fit-only thresholds (volatility, trend, event amplitude/age and direction as appropriate); comparisons without overlap remain unidentified. A shape permutation within valid state/time blocks can be a diagnostic in a separately authorized protocol, not a substitute for chronological validation. It must preserve state and event clustering rather than shuffle dependent prefixes across time.

Primary outcomes should match the event question: correction depth/duration, continuation versus failed/reversed move, and barrier-first/time/no-hit probabilities on a fixed horizon and original physical risk scale. Compare proper losses, calibration and event-level paired uncertainty against the simple controls; predeclare an economically meaningful effect and enough independent events before fitting. Report direction and stop-conditioned Q separately, as well as joint compatibility. An improvement must persist across folds and failed/truncated cases, not arise only from selecting completed successes or good regimes.

**Decision:** existing recipes have not established market/path skill or economics. Event-based learning is plausible and untested; the strongest justified next work is a frozen causal event dataset/target/sampling specification with simple state/event priors and explicit failure/censor accounting. No new computation or next experiment is launched by this audit.
