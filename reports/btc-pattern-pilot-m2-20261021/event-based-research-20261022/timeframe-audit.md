The main protocol **plans** both H4 and H1 (`features.timeframes_hours=[4,1]`, `bars=64`); default source construction and completed findings together establish that local baseline execution used both. Optional 15m was conditional on positive main BTC evidence and was not admitted. H1 was therefore already present; the untested question is its incremental value, alone and with H4, under comparable history and resources. H4-only CatBoost is the one documented completed resolution control, with no significant superiority of the two-frame alternative established there. A failure to reject a difference is not equivalence.

## Physical lookback and causal timestamps

64 H1 candles span 64 hours; 64 H4 candles span 256 hours. Replacing 64 H4 with 64 H1 changes both resolution and available history. It cannot identify a pure resolution effect. Context itself needs 169 completed hourly bars. Engineered features also depend on previous closes and previous-20-bar volume baselines; source records `engineered_input_start=raw_input_start−80h` for the H4-dependent descriptor. Equal visible candles do not imply equal total information support.

In `features_at`, eligible index is `searchsorted(t + tf*HOUR, origin, side='right')`; slices end at that index. Thus an H4 candle timestamped by its **opening** time is usable only when `open+4h <= origin`. Origins are hourly, so the latest closed H4 candle may be 0–3 hours old; this age is explicitly in context. H1 similarly requires `open+1h <= origin`. Entry is origin+60 seconds and is not an input. Panels are prepared from genuine minute data by the imported `aggregate` function. Whole-file offline aggregation is not itself future leakage if only complete causal bins are indexed. The aggregate implementation was outside this bounded read, so this is a source-contract finding, not a fresh full resampler correctness audit.

Any future dataset must keep UTC bin alignment, explicit start/end timestamps and closed-bar cutoff. At an origin inside an H4 bin, neither that bin's final OHLCV nor its eventual extremum may appear in input. No centered bins, backward-filled future closes or completed-event hindsight boundaries. Verify offline versus sequential prefix equivalence before a separately authorized run.

## Bounded proposed ablation, not launched

Use one simple fixed model family and **three arms: H1-only, H4-only, H1+H4**. Freeze the same causal event IDs and query/confirmation times, full-history expanding folds, event weights, purge intervals, failed/truncated/censor handling, physical 72h targets, entry prices, σ72 and physical stop levels. Preserve the same 12 context fields in the primary comparison and label arms precisely as *sequence-resolution* ablations: shared context contains H1 information even in the H4-sequence arm. If eliminating that information is desired, it is a distinct context ablation and should not be added silently.

For the primary resolution comparison, align every query to the latest fully closed H4 endpoint B and present the same physical interval [B−256h,B): H1 gets 256 bars, H4 gets 64, combined gets both. Include origin−B age identically in all arms and freeze identical feature warmup support. This alignment intentionally withholds the most recent 0–3 closed H1 candles from every arm; it estimates resolution over a common history. At H4-aligned query origins there is no such withholding, but selecting those origins changes the population and must be declared. A comparison using latest available H1 through origin instead estimates a deployable resolution-plus-freshness bundle.

Record token/candle count, parameter count, optimizer updates, wall time and memory. Keep the downstream head, training schedule and predeclared resource cap fixed; use shared branch weights or a common bottleneck where feasible to prevent a second branch from simply adding capacity. For GPT, hold model, prompt, examples, context, output schema and output budget fixed; report input tokens. Lossless H1 and H4 views of the same 256h interval inherently have different token counts, so exact equal-token and equal-information claims cannot both be made without additional compression. Freeze the representation and report that limit instead of calling more tokens an H1 effect.

A same-64-bars comparison (64h H1 versus 256h H4; combined 128 candles covering a 256h union, with the last 64h represented at both resolutions) can answer a separate fixed-candle-budget practical question. It cannot replace the common-physical-history primary comparison. Predicting 72 H1 bars versus 72 H4 bars would additionally change the future horizon from 72h to 288h; keep future **hours**, not future bar count, fixed.

Evaluate paired event-level proper losses and uncertainty against state-only and event-conditioned empirical priors. Test all failed/censored strata and retain all calendar folds; do not select the best timeframe after seeing favorable months. A documented difference would support the frozen resolution contract only. No new encoder family, fitting, packet generation or evaluation was started by this audit.
