## Architecture and interface findings

TCN (`btc_pattern_models.py:7–28`): two independent branches, six residual blocks each, two kernel3 convolutions per block, dilations1,2,4,8,16,32, explicit left padding only, dropout0.1; final time state is concatenated, not temporal average pooling. Theoretical receptive field `1+2*(3−1)*sum(d)=253` bars exceeds the64 available. Perturbing positions32 onward changes no earlier branch output (exact max difference0). Heavy padding is a design limitation, not a causal error. In the dilation32 convolutions the offset64 kernel tap is always outside the64-bar input; it cannot observe data. Removing unused taps can only save limited arithmetic/parameters and is not evidence of forecast improvement. The construction is TCN-inspired, not an exact reproduction of Bai et al.'s weight-normalized ReLU recipe. [TCN paper](https://arxiv.org/abs/1803.01271).

CNN (`btc_pattern_models.py:30–35,62–73`): two fixed112px panels; each64-bar view independently maps log-price extrema onto78 vertical intervals and volume/max-volume onto20 heights. Candle colors/body/wicks are preserved, but price/volume precision is discarded and cross-panel amplitude comparison is weakened. A1.10e−6 synthetic OHLC change produces byte-identical pixels in the deterministic probe. The12 context variables partly restore volatility/state but cannot reconstruct all lost candle precision. Three stride2 convolutions with GroupNorm/GELU followed by global average pooling produce128D. This is a small trained chart-image encoder; no visual foundation model is present.

Kronos (`btc_pattern_smoke.py:8–45`): pinned model/tokenizer loaded strictly, SHA checked, `eval()` and gradients disabled; no finetuning of backbone/tokenizer. Six inputs are OHLC,volume,amount; amount=volume×mean(OHLC), per-window/per-field mean/std+1e−5 then clip[−5,5]. This amount fallback and normalization match the pinned official predictor (`model/kronos.py:519–547`), so the proxy is not a discovered interface bug. Timestamp order minute,hour,weekday,day,month matches upstream. Each1h/4h64-bar view is tokenized with `half=True` (returns the two token components), then `decode_s1` returns post-RMSNorm512D context; last states concatenate into1024D. `half=True` does not request half-precision model weights. No sequence padding is needed for complete64-bar views. Both upstream tokenizer TransformerBlocks and backbone self-attention are causal; whole-known-window normalization can depend on later bars inside the same observed context, which is valid for a last-state origin forecast. The cache is a frozen representation extraction experiment, not Kronos-generated OHLC paths. [Pinned official implementation](https://github.com/shiyu-coder/Kronos/blob/67b630e67f6a18c9e9be918d9b4337c960db1e9a/model/kronos.py), [Kronos paper](https://arxiv.org/abs/2508.02739).

Kronos pretraining corpus overlap with early DEVELOPMENT periods is not established absent a symbol/time corpus manifest. The paper's broad multi-exchange pretraining claim cannot certify a historically deployable2024/early2025 backtest. Pinning weights prevents drift but does not prove training-data temporal separation. The paper reports autoregressive rollout forecasting and OHLC-only crypto experiments, while this pilot uses six-field tokenizer input and frozen last-context features plus a new head; this is a legitimate representation probe, not a reproduction of those crypto forecasting experiments. Do not call observed negative frozen-feature results an independent historical zero-shot trial without that provenance.

All heads share normalized affine projection followed by separate affine D and Q readouts (`btc_pattern_models.py:19–22`); Kronos projection has no hidden nonlinear MLP beyond L2 normalization. D uses three dimensionless probabilities after softmax; Q is unconstrained2×3 normalized-MFE outputs. Training pinball divides each side by fit MAD but does not change predicted Q target units; evaluation uses original sigma72 units. Sorting/nonnegative projection occurs at saved inference, not inside raw training loss. Existing artifacts retain raw-crossing and projected-zero diagnostics; the absence of a built-in monotone/nonnegative parameterization is a limitation, not an unreported bug.

## Metric meaning and minimal options

The auxiliary loss is a custom outcome-neighborhood KL objective, not standard supervised contrastive classification. Its12-coordinate signature contains terminal returns and barrier touch times; it does not enforce agreement on the exact D first-event label or stop-truncated MFE quantiles. Similar terminal samples/touch times may hide different event ordering or path shapes. No theorem in the supervised contrastive literature establishes this signature as sufficient for72h barrier forecasts. [Original SupCon paper](https://arxiv.org/abs/2004.11362) supports normalized temperature-scaled supervised embeddings as a general method, not this task-specific distance or a financial performance promise.

1. Correct engineered-support metadata first, preserving old results and measuring saved-query reranking/score changes separately. This is the only confirmed implementation correction in this scoped audit.
2. Before any new metric fit, use saved signature neighborhoods to measure exact D disagreement and Q/MFE dispersion on the same purged matches, compared with numeric/random/prior. This tests target adequacy without introducing another model family. Existing METRIC_OFF market results already reject the simple claim that deleting the metric fixes forecast quality.
3. If a new recipe is separately authorized, retain the actual CNN/numeric controls and full history. A shared barrier-event head is scientifically more aligned with the intended joint D/TP/SL semantics than increasing image size, model size, epoch cap, or performing a blind architecture search. Its benefit remains unproven; the failure-followup proposal already records necessary freezes. This audit implements none of those changes.
4. Engineering-only optimization candidates: pre-sort/cache invariant per-fold prior Q values/weights in `empirical` (currently concatenated/sorted per query and side), exact batched cosine products, and remove provably unused TCN kernel taps. Preserve stable tie order, greedy72h spacing and weighted inverse-CDF convention; a generic top-k shortcut can fail because skipped nearby candidates may be required after spacing exclusions. These offer runtime savings, not evidence of predictive improvement.
