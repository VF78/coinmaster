# Full daily waves: methodological decision

2026-10-22. Analysis and proposal only. No daily segmentation, catalogue computation, new target, forecast, backtest, source implementation or data fetch was performed for this note. The existing 699-day interval `[2024-06-01,2026-05-01)` and its saved hourly catalogue remain intact.

D90 tested one binary trailing-return state at the existing H1 origins. It retained neither daily turning points nor a growth/fall leg followed by a correction. Its failed proper-loss gate is evidence against that particular conditional prior; it does not reject an untested complete-wave hypothesis. More granular states, an encoder or longer trailing return would not by themselves repair this mismatch.

A useful next object is an alternating-extrema triple **A→B→C**, accompanied by **D**, the later observation confirming C. A and C are lows around an upward main leg, or highs around a downward main leg. The correction may exceed the main leg and cross A. Such reversals must remain in the catalogue; selecting only corrections followed by profitable continuation would select on the answer. D confirms a threshold reversal, not a scientifically proven permanent correction end.

At a live query during the correction, B may already be confirmed, but C and D are unknown. The feature object is therefore **A→B→observed prefix**, never the final A→B→C curve, final duration, total correction depth, or a percentile of the eventual phase. A mature historical object may contain the full curve and endpoint outcome, but its matching features must be reconstructed at its own original causal query.

The accompanying proposal freezes one close-based directional-change definition at a fixed log-price threshold `δ=log(1.10)`. The threshold is an explicit, unoptimised design choice, not an empirical discovery or a promise of 100–200-day cycles. Completed-D1 closes remove intraday high/low ordering ambiguity. This may miss wick reversals. A 10% event scale is materially different from a 90-day sign; durations emerge from prices. If it mostly produces short oscillations, that fact must be presented to the owner before treating it as the intended macro-wave ontology. Do not change the threshold after inspecting counts to manufacture long waves or enough samples.

All available genuine D1 data from May15 initialise the detector. It is a finite-state, finite-observed-history algorithm; it is **not** a rolling 10/34/90-day feature. Its exact raw input support begins at the first seed bar and persists. Under the original complete input-support/label disjointness rule, every query carries that seed and historical training is empty. The proposal records that result and requests an explicit different validation contract if prediction is later desired: all labels are mature before the current main-leg start, all matching features reconstructed as of their own origins, and the same eligible library for all controls. Shared past detector inputs are then allowed and dependence disclosed. This is a change of contract, not a correction that makes the old purge disappear.

H1 has one fixed role: describe the last 24 completed hourly closes immediately before the D1 B-confirmation query. The daily prefix identifies the main move and observed correction; the H1 path describes the local reversal. H4 is not a second candidate. One query per B confirmation avoids turning dozens of child windows from the same cycle into nominally independent observations. Different triples still share legs, so even their count overstates independent evidence.

The conditional prediction question retains the existing H72/3TP-SL targets, applied to one macro query at B confirmation. It asks whether the actual D1 impulse and correction prefix improve those short-horizon forecasts beyond H1-only and unconditional controls. This is a full-wave-context test, not a forecast of the final C or ultimate cycle length. C/D and full correction depth remain descriptive catalogue fields. Since rising and falling path shapes are sign-aligned, the conditional design also proposes a transparent common side-axis permutation: unchanged raw long/short outcomes become WITH_IMPULSE/AGAINST_IMPULSE for historical aggregation, then map back to raw long/short using the known query impulse direction. All three arms use this mapping; undefined direction is unsupported. The raw target function remains unchanged, and this outline requires later approval before implementation. The entire699-day period remains; initialisation, left-truncated and right-censored rows remain visible, with explicit missingness or fallback rather than selective dropping. Any new macro-query forecast requires separate owner approval.

699 days contain only about 3.5–7 nominal 100–200-day durations; this is arithmetic, not a measured cycle count. Initialisation, left truncation, endpoint confirmation and right censoring can reduce usable support. More H1 observations cannot manufacture independent full cycles. The next useful answer may simply be **insufficient sample for this hypothesis**. Catalogue first, forecasts only after a separate explicit decision.

Primary sources support the method boundary, not a BTC performance claim:

- [Glattfelder, Dupuis & Olsen, *Patterns in high-frequency FX data*](https://www.research-collection.ethz.ch/items/5d0573b3-a0bf-4502-9e6a-245c9f7a5e62): event scales and directional changes offer an alternative to fixed clock intervals. The paper's FX empirical laws do not validate a 10% BTC detector or forecast edge.
- [Golub et al., *Multi-scale Representation of High Frequency Market Liquidity*](https://arxiv.org/abs/1402.2198): directional changes and overshoots define event-based states at multiple scales. This supports distinguishing macro and local temporal roles; it does not require testing a grid of thresholds or timeframes here.
- [Yeh et al., *Matrix Profile I*](https://ieeexplore.ieee.org/document/7837992/): nearest-subsequence/motif discovery is a similarity primitive. Similar historical shapes alone do not establish predictive skill, causal availability or independent examples. The proposal deliberately does not add an all-length motif search.
- [Hyndman & Athanasopoulos, *Time series cross-validation*](https://otexts.com/fpp3/tscv.html): rolling-origin training uses only earlier observations. Here label end/confirmation availability must be checked in addition to feature dates. Chronological availability does not make overlapping observations independent.
- [Gneiting & Raftery, *Strictly Proper Scoring Rules, Prediction, and Estimation*](https://doi.org/10.1198/016214506000001437): probabilistic forecasts require proper scoring. Matching visual waves and TP reach frequencies cannot replace forecast-loss comparison. No ROI, drawdown or tradable-policy conclusion follows from the proposed descriptive or forecasting stages.
