# Nautilus: уточнение методики готовности — 29.10.2026

Статус: изучены официальные документы и обсуждения с разработчиками. Это уточнение проверки текущего релиза, не разрешение на live, новую экономическую серию или смену движка.

## Что меняем сейчас

1. Единственный источник позиций, ордеров и денежных событий — native Nautilus Cache/Portfolio и подтверждённые события. Не воспроизводим второй OMS в тесте.
2. Для C1 проверяем наблюдаемый результат: после частичного TP и подтверждённой отмены оставшейся части защитное сокращение проходит один раз; нет переворота/дубликатов; затем TP защищает фактический остаток. Пустота частной очереди не является самостоятельным бизнес-критерием.
3. Реальная гипотеза по A19: обычный TP перепланируется после cancel и обгоняет C1. Исправляем приоритет производителей в существующей live-стратегии, без обхода RiskEngine, ручной очистки очереди или новой системы ордеров. Исход пока не доказан полным native-проходом.
4. Сначала узкое воспроизведение на реальных объектах/методах, затем один связанный набор регрессий и независимое ревью. Новый физический сценарий только после заморозки. После успешного A — B с теми же DB/source/fixture; успешный A не повторяем.
5. Рукописный клиент оставляем только для сценариев ACK/lost-ACK/late-fill; не заставляем его произвольно определять правила matching или порядок native-событий. Для будущих обычных сценариев предпочитаем stock Sandbox/короткий BacktestEngine replay. Полную замену текущего fixture до завершения не начинаем.
6. Проверки UI/документов/фикстуры не требуют повторения 24-месячной экономики. Изменение реальной семантики исполнения должно получить отдельную оценку сопоставимости с победителем; нельзя автоматически объявлять его экономически нейтральным.
7. Simulation не доказывает поведение биржи или сетевые задержки. Реальные операции — только после отдельного START владельца. Тестовый PASS не равен готовности всех условий live.

## Подтверждённые рекомендации и подводные камни

- [Официальная методика тестирования](https://nautilustrader.io/docs/latest/developer_guide/testing/): выбирать минимальный полезный слой, проверять наблюдаемые эффекты, повышать уровень только при необходимости. Latest — рекомендации по методике, не обещание наличия API в установленной 1.231.
- [Sandbox v1.231](https://github.com/nautechsystems/nautilus_trader/blob/v1.231.0/nautilus_trader/adapters/sandbox/execution.py): native wrapper над симулируемой биржей; [обсуждение задержек #1677](https://github.com/nautechsystems/nautilus_trader/issues/1677) поясняет ограничения локальной симуляции.
- [Hyperliquid v1.231](https://github.com/nautechsystems/nautilus_trader/blob/v1.231.0/docs/integrations/hyperliquid.md): частичное IOC-исполнение и отмена остатка; modify как cancel/replace; batch submit не доказывает поддержку биржевых bracket-ордеров.
- [Maintainer-confirmed #5104](https://github.com/nautechsystems/nautilus_trader/issues/5104): отмена частично исполненного входа могла отменить защитные bracket-выходы, проблема подтверждена также в 1.x. Поэтому миграция на brackets не является быстрым доказанным исправлением текущего C1.
- [#5348](https://github.com/nautechsystems/nautilus_trader/issues/5348) и [#5366](https://github.com/nautechsystems/nautilus_trader/issues/5366): полезные предупреждения о reduce-only/sandbox reconciliation, но воспроизведения относятся к 2.0rc. Не приписываем их установленной 1.231 без собственного воспроизведения.

## Где терялось время

По 19 сохранённым процессным квитанциям суммарное время физических native-процессов — 813,20 секунды (13,55 минуты), при промежутке между первым и последним claim около 6 часов. Это не измерение токенов или всей CPU-работы; оно показывает, что узкое место — диагностика, переподготовка fixture, координация и повторные проверки между запусками. Ускорение должно сокращать именно этот цикл: один установленный дефект → точечный воспроизводитель → один автор/один рецензент → связанная проверка → frozen native. Не расширять перечень допуска после каждой локальной ошибки без конкретного нового риска.

## Реализация и backtest

[Lifecycle стратегии](https://nautilustrader.io/docs/latest/concepts/strategies/) отделяет конструктор от работы с зарегистрированными clock/cache/portfolio. Сохраняем штатный market_exit. [Bar execution](https://nautilustrader.io/docs/latest/concepts/backtesting/bar-execution/) требует учитывать время доступности бара и неизвестный порядок high/low. [Fill models](https://nautilustrader.io/docs/latest/concepts/backtesting/fill-models/) объясняет ограничения L1, ликвидности и проскальзывания. Прежний Bybit1m/syntheticL1 результат сохраняет эти ограничения и не является доказательством Hyperliquid PnL. Latest используется как методика; API проверяется на установленной1.231. Новых экономических прогонов обзор не разрешает.
