## One implementation-neutral strategy

Use a **read-only committed-native-state journal**, plus a deterministic paired completed-mark reader for retrospective valuation. The journal never sends/cancels orders, changes account/cache/positions, changes matching policy, updates trading marks or decides risk. It does not calculate fills, average cost or realized PnL.

- Seed a complete actual native snapshot before first exposure. Store native cash `Money.as_decimal`, immutable stock copies/bytes of every actual open native Position, account/instrument IDs, native fill/account/funding IDs, sequence/epoch and explicit position-state fingerprints. No mutable object references or floats for native Money/Price.
- Capture committed post-fill snapshots on `events.fills` before strategy callbacks; capture standalone committed account/funding mutations on `events.account`, correlated with actual funding journal records. Native quantity/commission/event counts are coverage assertions, not a substitute money engine.
- For a fill's PRE state, value the **last proven complete immutable actual native snapshot** at that fill's paired completed mark source. For its POST state, value the just-committed actual native snapshot at exactly the SAME paired source. Revaluation uses native Position.unrealized_pnl(native Price) only. A quote's `pre_process` gives an additional direct native pre-matching cross-check. Pre-open flat cash is an explicit snapshot, never inferred from post-entry inventory. This provides pre-fill/pre-open peaks without reconstructing a virtual account, provided all intervening mutations are proven covered.
- Paired prices must both come from the same completed-minute source u with `available_ns<=event_ns`; use native price precision and retain source open/available timestamp and raw→native Price conversion. For custom mark callbacks delivered sequentially at the same time, retrospective use of the complete source pair must be explicitly labelled observer-only, not a pair already delivered to a trading feature. If the clock has no such pair, stop/UNKNOWN; do not combine newest BTC with older SOL or choose asset extrema. Between minutes use only the latest genuinely completed paired source and record age, not future closes.
- Preserve all actual sequence-ordered event snapshots, including all same-time partial fills, fees and per-asset funding transitions. A continuously sampled minute series is a separate projection. Emit a “settled” receipt only after the actual command/data/timer watermark for that source has been demonstrated; `process(ts)` alone is insufficient. If that watermark is only known on later receipt, publish the immutable source-state snapshot with both sequence/source and actual receipt time, never the later current state. Event DD uses the sequence snapshots; settled DD uses the frozen minute convention. No favorable mixed-state ordering.
- After existing `engine.end()` RETURNS, take a direct native final snapshot. This stock end method flushes remaining timers and pending commands (N/backtest/engine.pyx:1381–1416); runner already calls it at F/runtime/coinmaster/research/native_baseline.py:986 and checks terminal flat/nonterminal orders at1042–1046. When actually flat, final equity is exact actual native cash+actual reserve; it requires no future mark, delayed custom receipt or synthetic terminal fill. Preserve pre-terminal/left-limit samples and boundary fees separately. Verify native terminal cash/report/funding parity before recorder.close; do not append a fabricated t−1ns terminal to the interval curve.
