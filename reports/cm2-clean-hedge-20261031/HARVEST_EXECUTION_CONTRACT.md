# Protected ordinary harvest execution

Ordinary BTC harvest uses native reduce-only LIMIT/IOC, post_only false, at the current executable bid for a long sale or ask for a short purchase. The shared admission function has already checked that quote against current native basis, allocated entry fees, adverse signed funding, expected exit fee and tick buffer. Native price coercion must preserve the exact executable value. This protects against a worse delayed execution price without a new parameter, loose threshold or minimum-notional discrepancy. Stops, fixed safety trims and parent/terminal drains keep native market IOC and explicit risk intent.

On each actual ordinary harvest fill, the adapter reads the native cached Position basis/entry and verifies remaining native quantity plus filled quantity equals its tracked before-quantity. It synchronizes the existing native funding reader, allocates native entry costs/funding pro rata, uses actual native commission/currency and checks net geometry strictly exceeds the tick buffer. Missing or inconsistent native facts produce UNKNOWN; nonpositive geometry produces FAIL. Either persists quarantine/drain. The actual fill, fees, funding, native cash and loss remain untouched. This geometry is an admission/structural audit, not another PnL or account authority. Native lifecycle/cash/fee/funding reports remain authoritative.
