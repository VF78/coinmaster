6. EP: МЯГКОЕ РАЗРЕШЕНИЕ ПО УСТОЙЧИВОМУ D1 НАПРАВЛЕНИЮ

Recipe B_WAIT_PERSIST_2D_025.
Самостоятельная альтернатива E4 на B, не комбинация E4+EP.

D=s*(C_D1-EMA34)/ATR14, то есть aligned distance неотрицателен для согласованной стороны.
ALLOW = (D>=0.5) OR (same_side_count>=2 AND D>=0.25).

Counter:
- начинается с1 на первом принятом D1 в новом WAIT;
- обновляется один раз на каждый unique accepted closed D1 при активном WAIT, даже если entry еще не eligible;
- прежняя raw-side -> +1; смена ->1;
- не считать повторные callback/quote/admission события новыми D1;
- пропуск/неполная D1 цепочка не означает два последовательных дня;
- после actual BTC fill счетчик/WAIT заканчивается.
Немедленная ветвь >=0.5 не ждет двух дней.

Read-only на сохраненном B пути: 12 из41 WAIT получили бы ранний допуск, в том числе20.04 вместо22.04.2025 и19.07 вместо21.07.2026. Но также24.12.2024 SHORT вместо25.12 LONG,28.10.2025 LONG вместо30.10 SHORT,08.08.2026 LONG вместо13.08 SHORT. Это не новые fills и не гарантия сохранения защиты.

Отдельный новый execution contract, НЕ установленное исправление бага.

Eligibility для arm:

- оба split-child/parent terminal; все entry fills/fees известны;
- до первого обычного BTC TP/reduction;

P0 исходный immutable PLANREF, A actual blended entry VWAP, c actual entry fees/actual entry qty, f действующая taker exit fee:
long feeBE=(A+c)/(1-f);
short feeBE=(A-c)/(1+f).
G=ceil_to_tick(max(P0,feeBE)) для long;
G=floor_to_tick(min(P0,feeBE)) для short.
Это floor по торговым комиссиям, не по funding. Не обещать net0 при gap/slippage.

Максимум один trigger на BTC episode; повторы допускаются только для исполнения уже принятого конкретного residual target, не для нового arm.
Количество = remaining eligible zero-slot lots, ограниченное фактическим BTC и уже зарезервированными reductions.
Для B50 исходный zero-budget, ЕСЛИ нули подтверждены:59.814BTC.

При появлении ordinary TP/D1 fallback, REGIME/TRAIL, SOL increase или изменении eligibility отменять/согласовывать guard. Приоритеты реализовать через cancel ACK и обработку late fills, а не одним if.
Не менять положительные TP, P0, grossQ, beta/H или первоначальные плановые знаменатели.

9. ОГРАНИЧЕННЫЙ НАБОР FULL NATIVE

Не более8 основных прогонов:
P0: новая кодовая ветка, все новые flags OFF, исходный B ON; подтвердить прежнюю экономику.
E4: B+WAIT4H.
EP: B+PERSIST2D025.
Z: B+ZERO_RETRACE, если causal precheck подтверждает ноябрьскую достижимость.
S: B+SOL_DOMINANT_CUT, если causal precheck подтверждает действие до раннегоDD50.
XZ: выбранный E* + Z.
XS: выбранный E* + S.
XZS: выбранный E* + Z + S.

E* выбирается из B/E4/EP, не из произвольных новых рецептов:
1) если есть 50/90 — максимум TOTAL среди проходящих;
2) иначе если есть retention>=90%,DD<=S0, no liquidation — минимум global DD среди них;
3) иначе максимум TOTAL среди DD<=S0, no liquidation;
4) ties: меньший DD, затем меньший turnover.
Если E*=B, не повторять дубликат BZ/BS.
Комбинации запускать только для корректных, реально активных компонентов; отсутствие отдельного 50/90 у компонента НЕ является запретом комбинации. По одному компоненту невозможно автоматически устранить все три разных риска.

Не выбирать даты/episode IDs для действия, не менять TP/EMA/плечо одновременно, не оптимизировать all-history thresholds, не добавлять CNN/LLM/новыеhedges. Не повторять H4/C0: они разрушали lifecycle и ликвидировались раньше эффектаB.

До 4 дополнительных контрольных прогонов только при проходящем или близком Pareto-кандидате:
- свежий repeat с теми же seeds/config/input в одном окружении;
- один adverse execution-cost stress, например дополнительный 1 bp на fill notional через тот же native account path (не постфактум вычитание при неизменном sizing);
- до двух локальных neighbors одного активного параметра, выбранных до просмотра результатов: для E4 band 0.45/0.55; для EP weak band 0.20/0.30 при unchanged strong band 0.5; для S adverse 1.8%/2.2% при unchanged DD40. Выбрать ровно одну такую пару по компоненту, давшему основное улучшение.
Z не имеет подбираемого MFE-порога; для него stress costs/one-minute delay, а не сетка стопов.
Если никто не проходит и нового измеримого механизма нет, остановить набор и выдать Pareto-таблицу; не заполнять бюджет случайными переборами.

10. ВЕРИФИКАЦИЯ И РЕЗУЛЬТАТ

Сфокусированные проверки:
- закрытые D1/4h/H1, одинаковый timestamp, без lookahead и поддельных paired sessions;
- B latch только по actual fill; no-fill/cancel сохраняют WAIT;
- Z ordinary TP versus risk-stop, partial/cancel/late fills, correct retired-lot budget, no SOL rights;
- S cancel/add race и отсутствие автодобора/искусственного rearm;
- new flags OFF parity с B.
Не переделывать всю test-систему и не писать тесты только на формулу, повторяющую implementation.

Для каждого прогона:

Основной DD расчет — по native marked equity после settlement на исходных причинных marks; не по cash, не по PnL закрытых сделок, не по синтетическому одновременному OHLC-экстремуму. Учитывать funding cash mutations/fees и terminal cash bridge. Missing receipts = unknown/lower bound, не нулевой риск.

Отдельный episode-ledger для A/C/D и всех новых максимумов:

почему улучшился DD, почему изменился ROI.
Сопоставление PnL старых эпизодов — descriptive; итог новой политики только native.

Старый 24m период многократно использован для отбора; его хронологические срезы НЕ называть fresh OOS.
