# Источник данных определяется биржей исполнения

Задание владельца от 30.10.2026: реализовать единый источник стартовых и торговых данных по бирже исполнения; Hyperliquid live использует только Hyperliquid. Последующая оптимизация сохраняет исходный эталон Bybit. Реальные заявки и START требуют отдельного подтверждения владельца.

## Границы реализации

База продукта — `4ca0d87993f28c20fb039840551c04e051378582`. Единственный исполнитель меняет изолированный VPS-worktree `research-worktrees/venue-bound-live-20261030`, ветка `codex/venue-bound-live-20261030`. Mac содержит управляющие документы. Исследовательские исходники, данные и финансовые результаты сохраняются.

В live биржа фактических BTC/SOL execution IDs определяет один binding: инструменты сигналов, D1/M1, разогрев, C1 seed, транспорт, происхождение данных и checkpoint identity. Несовпадение бирж или неподдерживаемая биржа завершают подготовку с ошибкой; межбиржевого fallback нет. Наличие Bybit data binding не означает квалификацию Bybit live-исполнения.

Режим исследования задаётся явно: прежний Bybit reference допускается вместе с прежней документированной моделью правил исполнения Hyperliquid. Этот режим не получает права на реальные заявки. Формулы и 39 параметров BTC, SOL alpha/staging, C1, USDC и DP55 не оптимизируются в этой задаче.

Для stock Nautilus 1.231.0 нормализуются открывающие timestamps HL D1/M1 в закрывающие, с сохранением действительного времени доступности и точных Price/Quantity. Незакрытые/поздние/повторные/неполные данные не превращаются в свежие сигналы. Новый источник получает собственную историю и идентичность; старые Bybit checkpoints не переименовываются, финансовое состояние не сбрасывается.

Для текущего разогрева HL достаточно проверенной postactivity D1 истории. Удаляется только начальный непрерывный неподтверждённый префикс; внутренние дни без торгов сохраняются. Недоступный глубокий HL M1 архив не заменяется Bybit. Новый 24-месячный HL экономический результат в этой задаче не заявляется.

## Проверки и пределы

Сначала — целевые engine-free проверки, реальные native Bar/Cache/Order объекты без создания TradingNode/BacktestEngine, затем один независимый аудит конкретного diff и торгового пути. Проверяются маршруты и запреты fallback, timestamps/UTC/парность/повторы/доступность, разогрев и provenance, восстановление и неизменность исследовательского маршрута.

После freeze исходников, устранения P0/P1 и отдельного GO координатора — максимум **6 новых инженерных native-попыток**, включая неудачные. Это ограничитель текущей реализации и её необходимых проверок, выбранный координатором; владелец не утверждал отдельное числовое значение 6. Старый закрытый экономический бюджет 10/10 не открывается и не переносится. Цель — уложиться в два основных сценария:

1. Полный путь нового binding и нормализованных данных через native runtime к решениям/заявкам и штатному завершению, с контролируемым транспортом без биржевых заявок. Доказать сохранение исполнения, USDC и защит; дополнительно проверить пропуски/повторы/запаздывание в том же сценарии, где это не искажает основной результат.
2. Новый процесс с той же DB: источник и clocks согласованы, капитал/HWM/DP/права не сброшены, несовместимый источник отвергается. Кэш не считается новым рыночным событием.

Остальные попытки — только при конкретном дефекте сценария или кода; без автоматического повторения тихого процесса. Каждая конструкция native engine/node заранее регистрируется в отдельном ledger с исходником, задачей и результатом. Полные экономические/prefix/обучающие запуски — **0**. HTTP/WS публичных данных, pure-тесты и native-объекты без engine не считаются физическим прогоном и учитываются отдельно.

Проверки не утверждают тождественность будущих реальных исполнений бэктесту, гарантированный предел потерь при разрывах цены или сохранение прежнего ROI после смены сигнального рынка. Старый результат A на Bybit сохраняет своё прежнее происхождение.

## Приёмка и передача

Один исполнитель, один независимый reviewer. Аудит включает путь источник→сигнал→BTC/SOL→TP/выходы→C1/DP→journal/restart, оставшийся живой Bybit код и мёртвые ветви. Проверяется сохранение точности/комиссий/USDC, отсутствие обхода UNKNOWN/ACK и отсутствие новых прав на реальные заявки.

Выход: точный commit, отчёт тестов и аудита с пределами доказательства, отдельный source/profile hash, закрытый инженерный ledger, обновлённые Project #101 и handoff. При готовности пакет собирается как отдельный неактивный релиз штатным способом; запуск и переключение рабочего live требуют явного START. Секреты, фактический баланс и приватные readbacks в публичный Git не попадают.
