## Causal algorithm, in order

All following code references are relative to `runtime/coinmaster/` at the exact scientific commit above.

1. **Daily signal and feature availability.** Accepted paired completed BTC/SOL daily sessions feed `FeatureState.append`. BTC close > EMA34 selects long; equality or below selects short. The EMA includes the just-completed close, not a future close (domain/wave_overlay.py:141–164). Beta is SOL-on-BTC covariance/variance over 270 daily log returns. With no episode, beta must satisfy strict `0.2 < beta < 4`, and completed same-side wave levels must exist. There is no active 15-minute reversal confirmation, EMA slope, ATR volatility sizing or entry-distance filter. Gating is not evidence these filters would help.
2. **Statistical TP levels.** `completed_wave_levels` excludes the dataset's unobserved initial regime and requires an opposite-side signal strictly before the current decision. For a same-side completed wave, reference entry is next-day BTC **OPEN**; favorable return samples DAILY CLOSES through the first opposite signal bar inclusive, clipped at zero. Waves ending inside a trailing 730-day window contribute; minimum 8 observations. Linear quantiles 0.10/0.30/0.60 become TP1/2/3 thresholds (domain:172–193). The minimum is a gate, not a proof of statistical precision; low-tail quantiles can depend on very few observations.
3. **Genuine episode and gross size.** A fresh episode freezes side, entry active marked equity, beta-entry and wave vector. Requested BTC gross notional = min(multiplier × marked active equity, 30,000,000); multiplier is 5.5 long and 7.875 short (domain:361–384; strategy/wave_overlay.py:945–950,1184–1239; native_baseline.py:1319–1321). These are exposure multipliers, not stop-loss risk fractions or exchange leverage settings. Actual active equity = native cash plus marked open native positions (strategy:1621 onward). Subsequent compounding changes quantities. Native lot rounding, current executable cap and margin admission can reduce/refuse size.
4. **q0/q1 selective zero netting.** At q0 freeze gross lots, original level lot allocations and wire reference. At a later fresh q1 with same accepted session, classify the OLD reference as passive versus executable side. Passive branch omits actual zero-threshold BTC allocations; otherwise retain full volume and suppress resting zero targets (strategy:1457–1529). Original fractions are 0.2125/0.2125/0.575; final allocation absorbs integer remainder. Omission is not a fill. Net planned denominator is normalized after q1 cap (1859–1865). Gross reference quantity persists for SOL H.
5. **Half entry, half discount.** Split actual accepted net lots: max(1,floor(lots/2)) first; remaining lots second. First leg uses actual native fill. Remaining leg posts GTC/post-only at first-leg VWAP × (1 − side×0.0025), rounded passively. Deadline = min(start+4h,next UTC day−1m). A positive TP price touch can trigger early completion; zero levels cannot. Deadline/early touch cancels existing limit then submits actual IOC residual only after its native ownership is resolved. Unknown ACK remains owned, preventing duplicate entry. Pause/forced close/day-boundary failure cancels/stops remaining parent (strategy/split_cover.py:88–206).
6. **PLANREF and money.** P0 freezes on completed first-leg actual VWAP; before completion management uses current blended native VWAP. P0 drives TP, daily fallback, best favorable return, trail and early-TP completion. Final actual blended VWAP/cash/fees/PnL remain native. H = gross reference BTC quantity × actual blended native VWAP / beta-entry (domain:475–560; split_cover:109–130). Substituting P0 into financial accounting would be wrong. H can remain large after BTC exposure is omitted or reduced; SOL coupling is material.
7. **Native TP and fallback.** Threshold target = P0×(1+side×threshold). TP1/2/3 use original planned fractions with integer native lots. Genuine positive targets rest reduce-only/post-only GTC after split completion. An already crossed positive target after completed accepted parent uses actual market IOC/taker, preserving level and residual ownership (domain:562–586; strategy:1904–1918; split_cover:186–194). Failed/uninstalled resting levels retain daily fallback if signed daily return reaches threshold; actual owned fallback leaves wait for an executable current quote that still satisfies threshold (domain:407–416; strategy:1412–1419). Zero full-entry thresholds can therefore cause delayed real IOC exits; no instantaneous or invented profit is implied. Generic `BTC_REDUCE` is not proof of zero threshold, since positive non-resting fallback has the same reason.
8. **Actual partial fill and SOL authorization.** Only real BTC reduction fills earn proportional rights, scaled to native completed lots and entry fraction; submits/ACKs do not (domain:495–525). Omitted zero allocations earn only a proportional right from actual net BTC fills; actual executable reference touch and accepted paired daily session activate it (domain:486–494; strategy:1531–1555). Reducing BTC changes subsequent opposite SOL opportunities, so isolated BTC PnL improvement does not imply portfolio benefit.
9. **Mandatory downside/group management.** Daily opposite EMA side emits REGIME CLOSE_ALL first. Otherwise signed daily return `f=side×(close/P0−1)` updates `best_f=max(best_f,f,0)`; TRAIL arms only when `best_f>.03` and exits when `f<=best_f−.03` (domain:388–395). This is a 3-percentage-point retracement of entry-relative **daily close** return, not an initial 3% loss SL or continuously observed 3% peak-price stop. Example long P0=100: daily close110 then107 triggers; no fill at107 is guaranteed. SOL mandatory timeout follows, and mandatory exits preempt ordinary pending work. Close native reconciliation owns both assets and cancels pending risk.
10. **Reentry.** Group is cleared only after native positions/orders and pending opening ownership reconcile flat; REGIME then immediately re-evaluates the same accepted current daily signal, permitting a fresh opposite episode. TRAIL has no immediate re-evaluation but may reenter the same EMA regime on a later accepted daily decision. No extra fixed cooldown/permanent trend lockout exists (strategy:2595–2611; domain:365–384). BTC TP-flat alone does not clear a still-owned SOL/group lifecycle. Each genuinely new episode receives fresh sizing, beta, wave vector and first-leg P0.
