# CODE0: расширение области знаков и tiers — аналитическое предложение

Для каждого инструмента положим σ=sign(actual held), q=|held| и r — уже исполненное сокращение. При 0≤r≤q остаётся σ(q−r): знак фиксирован до нуля. Поэтому signed shock PnL, стоимость выхода и фиксированная ограниченная стоимость исполненных единиц аффинны по остаткам при обоих знаках. Сценарии не обязаны быть симметричными: зеркальный портфель нужно заново вычислять через те же фактические пять shocks. Старая числовая лемма35.2044 для зеркала не переносится.

Первый tier не является математическим условием существующего prove_flat_route. Все три проверки baseline/route/full уже используют tier_partition_envelope. Он разделяет пространство остатков по всем scenario cap/price, MM-zero=deduction/(MM×price), нулю и изломам cost frontier; берёт точные floor/ceil native lots с соседями. В каждом прямоугольнике каждый scenario deficit и margin slack аффинен; проверка всех углов и двух сторон разрывов достаточна. Глобальная выпуклость margin не требуется. _mr_tier_boundaries возвращает Fraction, включая конечный последний cap; неизвестный/out-of-range tier должен оставаться UNKNOWN/DENY. Нужны полные frozen профиль/leverage, точные native lots, сценарии с положительными prices и непустой bounded universe. Количество проверок зависит от числа cuts, не от миллионов lot-единиц.

Таким образом, есть условное source-specific доказательство достаточности существующего partitioner для piecewise tiers и обоих фиксированных знаков. Это не доказательство готовности native adapter. В _mr_code0_old зашиты BTC≥0/SOL≤0, SELL старого BTC и BUY SOL-защиты; в _mr_code0_drain те же направления, диапазоны и dormant-неравенства. Удаление только входного guard небезопасно.

Стоимость старого close при σ=sign(held): k=σ(mark−limit)+limit×fee. Для long SELL это mark−limit+fee; для short BUY — limit−mark+fee. Сохранить доказанную maker-provenance на неизменённом limit, фактический ACK/leaves, per-lot fee-affinity, неотрицательный k и однократный учёт; не добавлять прежний frontier fee повторно. Новый close использует side=−σ, уже симметричный recovery_limit и ceiling per-lot комиссии. Его LIMIT IOC bound доказывает цену/стоимость, не исполнение.

Для SOLshort защита BUY: dormant TP limit<min(сценарии,book), STOP trigger>max. Для SOLlong защита SELL: dormant TP limit>max, STOP trigger<min. Строгие неравенства, trigger semantics, ACK, positive leaves, generation и одинаковые цены при pending resize проверяются и на admission, и при drain. Dormancy исключает только fixed-scenario/book universe; gap/path/latent triggers по-прежнему UNKNOWN. В drain sign остаётся исходным, |actual|≤|initial|, без переворота; после actual flat допускается только штатный drain положительных RO protection cancel ACK.

Контрпримеры простому удалению guards: shortBTC BUY108.8 при mark107 имеет loss1.82176/ед с maker.00020; старая long-формула даёт−1.77824. SOLlong SELL TP80 при book100 и shocks95–105 удовлетворил бы старому short-условию80<95, хотя ордер marketable; SELL STOP140 также удовлетворил бы старому140>105, хотя уже trigger-eligible. Tier endpoints без внутренних cap/MMzero cuts не доказывают margin внутри piecewise профиля.

Ограничения следующего единого протокола: только BREACH с положительным фактическим cushion и margin; один тот же baseline по полному заранее работающему universe; all partial≤baseline и full new-fill endpoint safe под независимо работающими old other-leg orders. Не разрешать increases или normal admission по этому benchmark. Positive native protection, ACK, неизменный deadline/peak/marks/features/binding и reproof после фактического drain сохраняются. При old/new сокращениях одной ноги exact full new-fill подразумевает нулевые old fills этой ноги; смешанный clipped-flat исход не равен этому endpoint и остаётся в route universe, с последующей проверкой фактического safe-state. Не обещать safe для любого flat mixed-cost исхода без отдельного доказательства.

Несколько обычных BTC TP уже поддержаны чистой математикой: old — tuple, а frontier сортирует каждый CID по его неотрицательной стоимости, берёт capacities в порядке убывания и разрезает по cumulative capacities. При фиксированном остатке q максимальная стоимость исполнения — этот fractional-knapsack frontier; любой иной порядок/частичные исполнения стоят не больше. Поэтому existing partitioner и prove_flat_route допускают несколько известных maker BTC LIMIT/GTC TP по различным ценам без нового PnL-моделя. Нужны aggregate leaves≤|BTC|, единый native lot, правильный close-side, distinct CID/parent/ACK, отсутствие pending mods, точная affinity/per-fill rounding и каждый per-CID cost≥0. Любое ограничение реальной совместной достижимости этих fills лишь делает полный rectangle/frontier консервативнее.

Native adapter пока не готов: len(old) запрещает второй BTC TP; отдельный guard требует фактический maker-fill history каждого. Поэтому при трёх targets или двух оставшихся обычных TP текущий CODE0 выдаст UNKNOWN; просто убрать len(old) недостаточно. Нет права объявить unfilled GTC maker только по типу ордера. Следующий согласованный проход должен доказать источник maker-классификации/price bound для каждого standing target или сохранить UNKNOWN для непроверенных. BTC STOP, новые trigger paths и opening orders не входят в это расширение. Все owners/capacities/generations/правила clipping должны остаться в source-bound universe; private queue claim не возникает.

Funding источники различны: engineering funding() явно создаёт zero8h fixture и запрещает считать его историческим settlement. Реальный _mr_snapshot читает config.research_method_a_funding и вызывает lagged_features: по каждой ноге берётся max суммы ABS известных causal rates за event-aligned24h окна предыдущих30d. Значения не зафиксированы в0; при наличии любого ненулевого prior rate соответствующий bound положителен. Источник конкретного будущего economic-prefix tuple и распределение ненулевых дней здесь не проверены — UNKNOWN, нельзя утверждать всегда0 или всегда ненулевые.

Для фиксированных известных конечных неотрицательных fund_b/fund_s существующий evaluate добавляет |B|×pb_scenario×fund_b+|S|×ps_scenario×fund_s. При фиксированном знаке это та же аффинная функция остатков, без новых quantity knots; loss и margin frontier proof сохраняются с пересчитанными коэффициентами. Это отдельное условное доказательство допустимости известных risk-feature funding bounds, а не прогноз фактического будущего funding. Текущий zero-only guard остаётся действующим до прямого согласования расширения; UNKNOWN rates, неполные intervals, фактические cash/peak transitions без нового snapshot/reproof и неограниченный future funding — DENY. Native settlement, timestamp identity и absence/doublecount денежных transitions не доказаны этой линейностью.

Перед реализацией требуется новое прямое согласование signs/tiers: последнее quantity-only разрешение их исключало. Затем один consolidated code0 pass с целевыми engine-free доказательствами зеркала, tier-boundary neighbors/MMzero/finite-max, нескольких ordinary BTC TP, известных fixed funding bounds, cost-rounding и drain guards; отдельное ревью. Новый native case map обязан заново вывести cash/SECOND ожидания. Native/prefix/full0, cap18 и FAILED не меняются.

Данные root о прошлых native marknotionals BTC1108990.1088 и SOL1140300 выше первых caps300000/50000 объясняют практическую узость текущего guard. Они не доказывают достижимость/выгоду CODE0 или будущие состояния P3; свежие source/state/tiers/cost доказательства обязательны.

**Отдельное условие baseline для multiple TP.** Partitioner доказывает supremum объявленного independent-fill/cost-bound envelope. Это ещё не доказательство точного supremum реально совместно достижимых native paths с разными target prices, приоритетом, общей depth и better fills. Ограничения достижимости уменьшают old envelope, но увеличенный old baseline может ослабить сравнение нового recovery: консервативность верхней оценки сама по себе здесь недостаточна. Нужен явно согласованный SAME conservative-envelope benchmark как risk-семантика либо source-bound доказательство совместной достижимости baseline; не выдавать одно за другое. Пример абстрактного препятствия: два old CID при реальном общем лимите fills1, каждый с capacity1 и cost1; independent envelope допускаетcost2, хотя native максимумcost1. Маршрутcost1.5 проходит inflated baseline2, но хуже настоящегоbaseline1. Это не утверждение о фактическом текущем BTC matcher; оно показывает необходимое условие переноса proof на несколько targets. Для ordinary TP descending-cost порядок может совпадать с price priority, но эту native связь здесь не доказывали.
