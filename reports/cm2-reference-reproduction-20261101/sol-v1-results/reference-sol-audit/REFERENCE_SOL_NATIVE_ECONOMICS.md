## Почему Stage5/6 не опровергают эти25 native cycles

Сравнивались разные решения, не одна стратегия с разными отчётами:

- A: один SOL book, actualBTCfill-earned persistent rights, D1/late-permission clock, first-fillσ lock, полный parent admission и staged1000SOL children; weighted native размеры и исполнение.
- Stage5/6:132 независимых M5 false→true labels, conditioning на другом BTC-only control с83cycles против84combinedA, динамическаяσ и отсутствие fill-earned rights/admission/staging. Labels перекрываются и не являются портфелем.
- Совпали только3 из25 начальных ns+SOL-side (cycles2,7,13). Даже они выходят по разным правилам: Acycle2 REGIME12октября против Stage5z21октября; Acycle13 REGIME13апреля против Stage5z19апреля. Stage5 может пережить несколько новых BTC и80дней; Stage6 все132label закрывает по новомуtrail.
- У Stage5 control actualBTCheld по его strict-prior convention в17 из25 исходных моментов. Поэтому нельзя буквально утверждать, что его predicate исключил все13 original-flat entries: исходные native состояния, другой контроль и порядок внутри одного ns различаются.
- Среднее unit SOL price return, включая многократно один режим, не сравнимо с суммой actual native realized+funding и капитализацией размеров. Финансовый вклад SOL не равен разнице двух независимых BTC-only TOTAL.

**Вывод:** Stage5/6 NONE остаётся верным для этих новых правил. OriginalA действительно показал прибыльный SOL alpha/staging внутри своей native модели. Но он не подтвердил новый контракт «нет входаBTCflat, KSTD60 size, независимый exit послеBTCregime»:22/25 его выходов зависят отgroup close. Нельзя объявлять5.6m BTC-only результатом или обещать716k с новыми размерами/выходами. Новых гипотез/подбора здесь нет.
