# SOL/BTC: одно окно и две разные формулы

**Заранее заданный критерий выбирает N=60 для буквального среднего дневных отношений. Однако эта формула сильно искажена почти нулевыми BTC-return.** Рекомендация для коэффициента именно волатильности — явно согласовать `Kvol=std(rSOL)/std(rBTC)`, также с единым N=60. Смысловая замена здесь не закреплена: immutable contract остаётся NOT_LOCKED до решения владельца.

## Буквальный запрошенный расчёт

`r_X,d=(close_X,d / close_X,(d−1))−1`; `a_d=|rSOL,d|/|rBTC,d|`; `K_N=mean(a_d)` по последним N завершённым UTCдням. При BTC-return0 — UNKNOWN, без пропуска дня, подстановки0, ограничения выбросов или winsorization. Полные Decimal значения precision50 — в `REQUESTED_15_ROWS.csv` и `RESULT.json`.

Для каждого asof последний использованный день —31августа. Дневная свеча допускается только при `open_time+DAY≤asof`; return требует предыдущий close. Использован обычный execution `close`, не `mark_close`.

## Причинное сравнение всех окон

Протокол записан до сканирования. Для каждого asof взяты180 завершённых целевых дней до него —05марта–31августа соответствующего года. В каждый день K_N рассчитан только по предыдущим N дням. Сравнивается `K_N×|наблюдавшийся BTC-return целевого дня|` с `|наблюдавшимся SOL-return|`. Это проверка **условной амплитуды**, не прогноз BTC-return или направления SOL.

Критерий выбора одного N: минимальный pooled WAPE по всем540 целевым дням; CV только при ничьей. `WAPE=Σ|prediction−actual|/Σactual`; `CV=sampleStd(K_N)/mean(K_N)`. Ни дата, ни BTC-сторона, ни DD не выбирают N. Все варианты имеют540/540 валидных predictions на одинаковых днях.

Данные не ограничивались и не исправлялись.

## Относительная волатильность — отдельная диагностика

`Kvol_N=sampleStd(rSOL)/sampleStd(rBTC)` на одинаковых N returns, `ddof=1`. `β=Cov(rSOL,rBTC)/Var(rBTC)` — signed beta; `ρ` — correlation, причём `β=ρ×Kvol`. Они не взаимозаменяемы. Диагностический walkforward использует те же условные амплитуды и дни:

## Конкретный следующий контракт

Владельцу нужно явно выбрать смысл: буквальное mean дневных отношений или отношение standard deviations. **Не подменять первое вторым молча.** Для обоих рассчитанных смыслов единый рекомендованный N=60; по цели «относительная волатильность» математически предпочтителен Kvol60.

После выбора формулы: обновлять по завершённым UTCдням; при начале торгового эпизода сохранить тогдашний coefficient snapshot и не менять его до завершения эпизода. Один N применяется ко всем датам и экспериментам. Недостаточная история/нулевой denominator дают UNKNOWN, не0. Здесь snapshot и стратегия не реализованы, immutable contract не изменён.

Первый return UNKNOWN из-за отсутствующего предшествующего close, но не входит ни в одно запрошенное окно/проверку.
