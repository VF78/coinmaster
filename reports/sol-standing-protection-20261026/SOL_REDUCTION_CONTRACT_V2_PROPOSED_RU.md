# SOL reduction contract V2 — решения R1/R2, report-only

**PROPOSED / NOT IMPLEMENTED.** Source8a, tests, native и ledger не меняются. Текущий HARD STOP сохраняется; лимит и будущие native количества здесь не предлагаются. V1 остаётся immutable evidence; этот V2 явно выбирает standard cancel/retiring и supersedes прежний audit-кандидат modify-to-zero. Никакого zero-total modify.

## Общий неизменный invariant

Только validated existing research SOL-standing family: standingBTC + SOL-standing + R2_A0_V1/B2_F0/current pair-owned native SOL position. OFF, TRIM без SOL и BTC core не меняются. Перед **каждым** native matching input положительные TP и actual STOP требуют current owner/history, exact current quantity/price/trigger и latest native ACK. Неизвестный, pending modify/cancel либо отсутствующий положительный TP/STOP — NO_GO. Positive allocations суммируются в actual held; STOP=actual held. Не засчитываются future fills, retired liability, planned exit или отправленная команда. Старые protection/debt/H clocks не меняются; retiring ACK deadline не даёт им grace.

Nonterminal SOL_CAP сохраняет положительные OID. Cancel/wait — только ENTRY; один existing public reduce-only IOC на causal SOL quote после точной защиты. ENTRY/другой CAP/CLOSE, pending mutation и retirement work сериализуются, дубли CAP запрещены. Каждый actual CAP fill, включая partial и terminal full-fill, через existing owner применяет существующие proportional tp_lots/caps/debt и немедленно согласует положительную защиту. Reject/deny/expiry — fault/NO_GO, не новый retry. Qty TP=actual filled+desired leaves, STOP=actual held, цены/trigger неизменны.

## R1 — выбран ровно один SOL exit owner

**Existing pair-owned SOL_CLOSE — единственный SOL exit owner для validated paired SOL position.** Реальный riskOFF/expiry/BTCflat/global regime/trail/terminal closing intent фиксируется у пары до первой cancellation; ENTRY/increases блокируются. Genuine closing сохраняет positive TP/STOP через actual partial/full public reduction до actual SOLflat. Только затем public cancel остатков и actual terminal ACK drain. Closing flag не является coverage bypass и не означает flat.

Generic `_begin_forced_close` делегирует SOL существующей паре. Оба generic dispatcher — `_submit_forced_close_on_quote` **и** `_submit_forced_closes_from_cache` — не создают второй SOL close. Они исключают из waitset **только точно validated owned positive SOL protection**, а не все reduce-only/SOL orders. Foreign, ENTRY, unknown, pending или другой reduction work остаётся blocker; отдельно распознанный pair-owned SOL_CLOSE означает единственный уже действующий owner, а не разрешение второго submit. Unknown ownership не приводит к fallback/adoption чужой позиции. BTC submit/price/qty/TIF/order logic остаётся прежним; разрешён лишь согласованный research SOL ownership filter вокруг generic waitset/delegation. Не подделывать `_forced_close_submitted` как будто неотправленный SOL order уже исполнен.

Pair-owned SOL_CLOSE обслуживает каждый actual exit fill через тот же actual rights/positive-protection reconciliation. Нужна bounded делегация completion в существующий global lifecycle после actual pair flat/drain, без early terminal/fill фабрикации. Source8a сейчас cancel-all и wait-all; существующий `_pair_quote` higher-close early return также должен делегировать одному owner, а не заблокировать его навсегда. Это явный implementation scope, не утверждение, что source8a уже выполняет R1.

Stock source подтверждает: close_position/all сами не cancel; market_exit делает cancel_all. Их применение не требуется: existing `_pair_submit` уже сохраняет предварительную запись native order/paired owner и IOC. Не вводить придуманные API kwargs, defaultGTC вместо IOC или новый OMS.

**Fault отдельно:** unknown/reject/lost STOP/partial IOC STOP — qualification NO_GO, допускается только существующий conservative native recovery. Не называть это CLOSING_PROTECTED и не расширять positive-coverage bypass. Любой STOP fill запрещает его modify/resurrection; partial STOP не получает финансовый PASS даже после flat. Engineering expected-negative требует заранее объявленного fault и actual final flat.

## R2 — конечный retiring ACK lifecycle

1. Zero desired TP может перейти в retiring **только из known latest ACK** current owned OID с actual history/filled/leaves и положительным сохранённым native unconsumed right. Причина — уже actual inventory reduction, никогда STOP/unknown/положительный desired TP. Pending modify сначала разрешается actual matching Updated; пока нет latest ACK, retiring exception не действует и strict следующая граница остаётся NO_GO. Cancel не конкурирует с pending modify.
2. Existing owner до public cancel фиксирует immutable original native liability, parent/side/strategy/instrument, cancel identity/time и trade/event dedup. Cancel однократный. Actual PendingCancel не является terminal ACK, filled или flat; open/inflight/work и liability остаются. Только эти перечисленные known retiring TP исключаются из required-positive TP set; положительная защита/STOP сохраняют весь strict invariant.
3. **Один parent-owned retirement episode:** `deadline_ns = first_retirement_cancel_ns + MINUTE`, MINUTE=60s. Срок фиксируется один раз и сохраняется до parent terminal; новые retiring OID, временно пустой набор, дополнительные late fills/ACK не перезапускают его. Одна cascade не получает новый episode/clock под тем же parent. Это максимум жизни ACK work, не protection/debt grace. На первом actual event/input с ns>=deadline, после учёта именно этого уже native-applied события и без заимствования будущих ACK, любая недостающая terminal ACK или unreconciled liability -> NO_GO. Последний настоящий ACK на deadline допустим лишь если он уже полностью закрывает history/liability; другой первый event на deadline не ждёт более поздних same-ts ACK. Новые таймеры/синтетические quotes не нужны.
4. Каждый validated late fill однократно дебетует immutable native liability; multiple fills/double delivery не возвращают rights/clock. Native TP identity/level/price/commission сохраняются. Только retiring-owner actual fill направляется в существующую proportional inventory-reduction арифметику оставшихся positive rights, затем actual caps/BTC debt/positiveTP/STOP ACK reconciliation. Иначе current TP clamp при desired0 даёт sum-rights mismatch — это source8a limitation, а не разрешение пропустить проверку. Qty сверх liability, unreconciled trade, неизвестный ACK/owner, missing positive sum/STOP — NO_GO. Native reduce-only clipping не заменяет actual history.
5. Actual OrderCanceled либо genuine terminal full-fill history снимают liability только после учёта **всех** actual fills. CancelRejected benign лишь как доказанный redundant reply **после уже настоящего terminal** того же OID/owner и полной reconciliation; stock `process_cancel` действительно может ответить not-found после удаления из matching core, но not-found сам по себе ничего не доказывает. Live/unknown/missing-trade CancelRejected -> NO_GO. Expiry, unsolicited Updated, invalid/missing ACK -> NO_GO; liability остаётся до actual history, не retry и не fake terminal. Increases, новый CAP и pair/right release запрещены до полного ACK/drain.

## Совместимость, минимальная реализация и replay scope — NATIVE0

Stock source не противоречит выбранным состояниям: public cancel имеет настоящее PendingCancel/terminal или CancelRejected; event FSM сохраняет terminal state при redundant cancel rejection; queued zero-latency modify/fill команды осушаются до следующего data input. **Это не native proof атомарности/late-fill correctness.** Retiring deadline — явно предложенное новое ACK-work ограничение на existing60s unit, не заявленное старым runtime правилом. Если public callbacks/stock matching не обеспечивают exact positive protection к следующей границе, STOP; никакого grace/waiver.

Минимальный будущий code scope после отдельного разрешения: paired_prefix (active/reducing/retiring/closing/fault state у existing owners, CAP/CLOSE actual callbacks, strict observer partition/deadline), guarded SOL delegation/filter в двух generic wave dispatchers/begin-close, и адресный real Cache/Order event replay. Без SDK/cache/link/money-engine изменений, новых supervisors/services или переключения variant внутри engine.

Минимальный engine-free replay table: (a) pending modify→latest ACK→one cancel; (b) zero TP PendingCancel с exact positive TP/STOP, несколько actual late fills, dedup/лиability/proportional rights/debt, genuine terminal ACK; (c) first event на/before/after immutable deadline, cascade не reset; (d) benign terminal redundant CancelRejected против live/unknown/missing-trade Reject, expiry/unsolicited Updated; (e) protected global partial exit, ENTRY/foreign/unknown blockers, quote/cache dispatchers вместе дают ровно один pair SOL_CLOSE, no early release; (f) cap full/partial/terminal/reject и STOP-fault/no-resurrection. Это построенные real native-class callbacks, **не matching/native economic PASS**. Сейчас replay и implementation не запускались.

Для нового source выбирается **fresh E1**. Старый E7/source8a остаётся только историческим component PASS; conditional reuse/noninterference proof не используется для qualification нового source. Новый integrated E5 обязателен. Полная future native case map и решение о лимите — только после фактического source, pure PASS и source review; чисел здесь нет. R1/R2 должны быть независимо закрыты как design, не как разрешение запусков.
