# Предложенный контракт обычного уменьшения SOL — только решение, не код

**Статус: PROPOSED / NOT IMPLEMENTED / native GO=false.** Source8a неизменён. Engineering4/7 HARD STOP, remaining3 HOLD, prefix0/4. Новый лимит не предлагается.

Существующий strict invariant сохраняется для **положительных TP entitlement и actual STOP**: перед следующим native matching input каждый обязательный OID известен, текущий parent/strategy/instrument/side/reduce-only/history подтверждены, количество/цена/trigger соответствуют actual inventory и последнему actual ACK; pending modify/cancel или неизвестный положительный TP/STOP дают NO_GO. STOP для held>0 никогда не становится retiring. Нет grace, новых quotes, TIF/latency/guard waiver или другого engine.

## 1. Nonterminal SOL_CAP с сохранением защиты

Обычный cap reduction отделяется от настоящего SOL_CLOSE. При actualSOL>неизменного solmax cancel касается **только owned ENTRY**, с ожиданием его actual terminal. Положительные SOL TP/STOP остаются теми же OID/ценами/trigger. Вместо нынешнего blanket `not _pair_work(SOL)` различаются protection и reduction/entry work. Ровно один existing public reduce-only market IOC допускается на обычном causal SOL quote после известных ENTRY terminal и точной защиты; никакого второго CAP, пока прежний CAP/CLOSE, ENTRY, pending protection mutation либо retiring cancel ещё живы. Qty берётся из actual current held и существующего cap, без anticipated fill/debt credit.

Каждый actual CAP fill применяет существующее proportional уменьшение tp_lots и существующий PairedCaps/debt учёт. Затем positive TP/STOP reconcile вызывается **в том же actual callback lifecycle**, включая full-fill terminal path. В source8a `_pair_terminal` вызывает protection только для TP/STOP; одного удаления blanket cancel недостаточно. TP total=actual filled+desired leaves; STOP total=actual held. Pending command/ACK остаётся у existing owner; следующая native matching граница требует latest actual ACK. Full/partial IOC terminal cancel пересчитывает только actual residual excess; отказ/deny/expiry остаётся существующим fault/NO_GO, не retry-маской. Native fill label, цена, комиссия и cash берутся только из actual engine.

## 2. Нулевой desired TP: retiring-owned-order, а не исчезнувший риск

Предлагается **явно изменить определение exact active protection**, а не просто исключить все PendingCancel из observer. Для zero desired TP применяется обычный public cancel, без modify total0. Existing owner получает retiring state **до** cancel, только если все условия доказаны:

- Причина — уже actual nonterminal inventory reduction; desired remaining для именно этого TP стал0 по текущему allocation. Это не неизвестный/положительный TP и не STOP.
- Совпадают original parent, OID, strategy, instrument, reduce-only, side, исходный native ACK/history. Native leaves/filled известны; сохраняются исходный unconsumed native right перед retirement, cancel event identity, actual fills и остаток liability. Owner/history/pending mapping не удаляются.
- Однократный public cancel и actual PendingCancel/history подтверждены. До ACK это **не canceled**, не filled и не flat. Native open/inflight/work counts продолжают включать OID.
- Все оставшиеся положительные TP и actual STOP имеют точные latest ACK и дают прежнее покрытие actual held. Никакой pending/unknown positive protection не получает исключения.
- Increases, новый CAP и pair/right release заблокированы до actual retiring terminal ACK и полной reconciliation. Старый TP не перевыпускается и не получает нового allocation.

Перед input проверяется разложение native protective work на exact positive protection и **только перечисленные known retiring TP**. Сумма positive allocations по-прежнему равна actual held; retiring leaves не прибавляются к защите и не вычитаются из exposure. Они отражаются отдельной конечной upper-bound liability: возможное дополнительное actual сокращение ограничено native remaining leaves и actual held при действующем native reduce-only. Никаких hypothetical fills/profit credits. Это уточнение допустимо только после явного принятия владельцем: меняется прежнее требование `len(work)==len(expected)` для конкретного known zero-right state, а не ослабляется проверка положительной защиты.

**Ключевой источник ошибки, который нельзя скрыть:** в source8a TP fill уменьшает только `tp_lots[level]` через `max(0,right-fill)`. Если desired этого retiring level уже0, late fill оставит сумму positive rights больше actual held. Поэтому proposed contract должен отдельно утвердить: **только validated retiring-owner actual fill** расходует его сохранённую native liability, затем оставшиеся positive rights приводятся к actual inventory существующим proportional алгоритмом non-TP inventory reduction. Original native fill сохраняет TP identity/level/price/fee; не переименовывается в CAP и не создаёт synthetic profit. Дальше немедленно выполняются actual cap/debt reconciliation и positive TP/STOP latest-ACK updates. Это явный новый dispatch condition к существующей арифметике, не утверждение, что текущий callback уже корректен.

Terminal ACK снимает retiring liability только по actual OrderCanceled/terminal filled history и согласованным cache/fill событиям. Поздний неизвестный trade, qty сверх сохранённой native liability, утрата owner/history, unsolicited/необъяснённый Updated, pending/неизвестный STOP, отсутствие exact positive sum либо ACK перед следующим input — **STOP/NO_GO**. Не принимать заранее native clipping как доказанный fill. Никаких новых protection/debt grace clocks: retirement с known risk не называется отсутствием положительной защиты, а неизвестная положительная защита по-прежнему запускает прежний protection clock. Pending age/expected transport/actual ACK сохраняются для проверки; своевременность не предполагается. Если обычный public cancel или late fill не позволяет соблюсти следующую strict границу, нужен отказ от этого refinement/другое явное решение, не waiver.

## 3. Genuine closing: защита до actual flat; fault остаётся NO_GO

Все изменения ограничиваются existing research SOL-standing family. OFF и TRIM без SOL не меняются. Actual riskOFF/expiry, BTCflat и global regime/trail/terminal close задают **реальный closing intent до первой cancel** и запрещают ENTRY/increases. Но `close_sol=True` само по себе **не освобождает held SOL от exact positive TP/STOP coverage**. Preferred состояние — `CLOSING_PROTECTED`: ENTRY отменяется/дренируется, known positive owned SOL TP/STOP сохраняются, один public reduce-only IOC сокращает actual native inventory. Каждый actual partial/full exit fill пересогласовывает positive rights/STOP через тот же existing owner/latest-ACK контракт. Лишь после actual SOLflat разрешена terminal отмена оставшейся защиты с actual ACK drain; pair/rights не освобождаются до всех native нулей. Planned exit, market order sent или closing flag не равны actual flat.

Установленные stock API проверены **по source**, без engine: `Strategy.close_position(position, client_id=None, tags=None, time_in_force=GTC, reduce_only=True, quote_quantity=False, params=None)` создаёт market order actual position.quantity и `submit_order(..., position_id=position.id)`; implicit cancel нет. `close_all_positions(instrument_id, position_side=NO_POSITION_SIDE, ...)` выбирает positions этой strategy и вызывает close_position, также без cancel. **`market_exit` иной:** он явно делает cancel_all_orders перед close_all_positions — он не подходит для данного preserve-protection контракта. У close_position нет придуманного `cancel_orders=False`; defaultGTC не должен незаметно заменить existingIOC. Existing `_pair_submit` public marketIOC/record_submission/owner registry предпочтительнее нового непредсвязанного close order; stock close_position возвращает void и сам не регистрирует paired owner.

В source8a generic `_begin_forced_close` сначала задаёт reason, затем cancel всех cache orders; `_submit_forced_close_on_quote` ждёт **все** open orders. Поэтому одного исключения SOL TP/STOP из cancel или одного раннего paired flag недостаточно: оставленная защита заблокирует нынешний dispatcher. Proposed contract требует единственного actual SOL exit owner в существующих registries: pair-owned SOL_CLOSE либо существующий forced-close owner, но не оба. Global dispatcher не должен повторно закрывать SOL или ждать именно разрешённую exact owned protection как blocker; чужие/ENTRY/неизвестные/reduction work остаются blockers. Actual closing partial fills обязаны попасть в тот же rights/coverage reconciliation. Точная bounded ownership/arbitration правка ещё должна быть выбрана и reviewed; новый OMS не предлагается. Неисполненная сериализация/двойной close/невозможный ACK — STOP, не bypass.

**Fault — отдельное состояние:** reject/unknown ownership/ACK, потеря actual STOP и partial native IOC STOP означают qualification NO_GO. Любой actual STOP fill запрещает modify/resurrection этого STOP. Full STOP с actual SOLflat ведёт к drain; partial STOP оставляет held inventory без гарантированного STOP и потому не может называться CLOSING_PROTECTED. Существующий conservative native recovery может закрывать actual остаток для безопасности, но exposure остаётся явно `FAULT_UNPROTECTED/UNKNOWN`, финансовый PASS запрещён; engineering expected-negative допускается только при заранее объявленном fault и actual finalflat. Closing flag не превращает неизвестную положительную защиту в PASS. Без новой позитивной гарантии не расширяется список fault/bypass. Known retiring zero-TP exception из раздела2 никогда не распространяется на STOP или положительный TP.

Если public reduction с сохранённой защитой, реальные partial/late fills и next-input ACK не укладываются в этот strict контракт, реализация/qualification **STOP** и требуется другое явное решение. Нет дополнительных quote/grace/латентности/TIF изменений и нет обещания, что source-only API proof уже гарантирует исполнение.

## Source facts, неизвестное и acceptance outline

Основания source8a: paired542–545 blanket cap/close cancel; paired669 zero-right cancel; paired311–333 terminal protection только TP/STOP; paired347–413 fill accounting; paired893–937 strict observer; wave2194–2229 global close reason перед cancel без немедленного paired flag. Native1.231 engine1892–1930 осушает zero-latency commands/callbacks до следующего data input; это поддерживает возможность immediate public modify ACK, **не обещает атомарность**. Native reduce-only clamp не заменяет actual history/ACK. Нужен actual proof partial CAP/retiring late fill/reentrancy: если он невозможен, контракт остаётся STOP.

До native допуска требуется независимое принятие retiring liability и его late-fill accounting, полного source diff и полного case map. Actual acceptance должен проверить: (a) ordinary SOL TP unchanged OIDs/latest STOP ACK; (b) full/partial CAP с сохранением положительной защиты и одним reduction owner; (c) zero desired TP PendingCancel с exact remaining TP/STOP, actual late fill в bound, последующий ACK и actual debt; (d) CAP reject/deny/expiry failclosed без retry; (e) genuine riskOFF/global close с сохранённой positive protection до actualflat; STOP partial как отдельный predeclared fault с recovery; (f) no unknown-positive exception, no increases/early release, actual final flat до cleanup. Существующие E2/E4/E5 общие P1 этапы не доказывают все эти края; complete integrated stage map ещё должен быть согласован. Ничего из этого сейчас не запускалось.

Actual E7/source8a сохраняется как старый PASS/component artifact. Reuse допустим только с actual branch trace (CAP/CLOSE submit0, ordinary BTC TP fill0, recordedSOL<=solmax), доказанной неизменностью всех посещённых функций/fixture/config/feed/advance и условием, что новые CAP/retiring/global-close ветки E7 не посещает. Новая integrated E5 должна выполнить новый source. Generic изменения в посещённом ACK/protection/closing path либо недоказанная noninterference требуют fresh E1. Нельзя автоматически перенести label PASS на новый source. Изменения genuine closing/protection dispatch также требуют branch-exclusion доказательства для E7; одной непосещённости SOL_CAP уже недостаточно.

**Самое дешёвое следующее решение:** независимо принять или отклонить именно эти три invariant/lifecycle условия и late-fill accounting; закрыть complete coverage map. Если exact positive protection/retiring envelope нельзя обеспечить stock public API до следующего input, STOP. Решения о реализации, native или бюджете этим документом не даны.

Самая дешёвая конкретная следующая проверка после отдельного разрешения: engine-free real Cache/Order event replay для retiring PendingCancel→actual late fill→positive-right proportional reconciliation→latest Updated→Canceled, с проверкой каждого следующего observer input и неизменности financial TP identity; отдельно source/AST proof единственного global SOL exit owner и E7 visited-path equivalence. Это ещё не matching/API-economic proof. Для actual partialIOC/reentrant matching и protected global exit потребуется заранее согласованный native case map; сейчас ни проверки, ни implementation не разрешены этим предложением.
