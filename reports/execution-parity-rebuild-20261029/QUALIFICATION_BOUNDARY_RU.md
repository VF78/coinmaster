# Что именно доказано совпадающим

Одинаковый код стратегии, конфигурация и одинаковая последовательность рыночных/account/order событий должны давать одинаковые решения и расчёты. Для текущего пути зафиксированы native Nautilus1.231.0, исходный BTC-профиль по39полям, общая USDC-модель допуска/размера/цен, текущие ограничения Hyperliquid и комиссии taker0,0432%/maker0,0144%. Деньги сверяются с фактическими native cash/fills/funding; внутри симулятора нет второго калькулятора торгового PnL.

Удалены скрытая зависимость обычных исполнений от тестовой глубины1000SOL и исполнение принудительных выходов по старой котировке. A превращает полезное ограничение размера в явное правило стратегии для всех обычных SOL IOC, без поддельного CANCELED: child≤1000SOL×фиксированный initialseed/10000 после полного исходного допуска parent. Следующий child зависит от настоящего terminal ACK и уменьшения native позиции; аварийные закрытия не ограничиваются. Настоящие частичные исполнения live остаются настоящими частичными исполнениями.

# Чего не доказывает эталон

Исторические данные — минутные Bybit, а не исторический Hyperliquid L2/сделки/очередь. Zero-impact full-fill — явное диагностическое допущение: рыночная заявка получает достаточную ёмкость для собственного остатка, maker исполняется только после пересечения. Из этого нельзя вывести гарантированное исполнение всех будущих IOC или maker-ордеров live, даже если исключить проскальзывание и funding. У live бывают частичные исполнения, задержки ACK, потеря соединения и недоступность площадки.

Текущие размеры, min-notional и margin tiers Hyperliquid применены честно. Их абсолютные границы, округление и минимальный размер не масштабируются вместе с депозитом. Поэтому гарантировать математически тождественные сделки на ЛЮБОЙ сумме невозможно: ниже минимума ордер запрещён, около границы tier меняется допустимая маржа. Вместо изменения правил площадки проверяется фактически доступный малый капитал отдельно.

Комиссии фиксируются для сравнения на текущем эффективном уровне. Реальные live-комиссии берутся из исполнений; будущий fee-tier может измениться. Funding остаётся исходным знаковым историческим потоком для сопоставимости и проводится в USDC; это не обещание будущего funding.

Raw native report сохраняет NOT_FAITHFUL_DIAGNOSTIC/ranking_eligibleFalse, поскольку исходных данных недостаточно для доказательства исторического реального рынка. Отдельный статус PRIMARY_OBJECTIVE_MODEL_PASS означает только достижение зафиксированных целей внутри объявленной модели и при точной финансовой сверке. Он не переписывает сырой отчёт и не означает разрешение START.

# Условия выпуска

Нужны полный модельный gate10K, отдельно фактический малый капитал, квалифицированные live-профиль/фиксированный initialseed/обработка fill в durable journal, сохранённые проверки полного цикла/перезапуска и venue-readiness. В live DP сохраняет45% от пика (DD55%). Автоматическое восстановление открытых позиций после неизвестного исхода сбоя не объявляется доказанным: применяется существующая ручная сверка. Реальный START — только после отдельного явного подтверждения владельца.

Официальные основания: [Nautilus backtesting](https://nautilustrader.io/docs/latest/concepts/backtesting/), [Hyperliquid IOC](https://hyperliquid.gitbook.io/hyperliquid-docs/for-developers/api/exchange-endpoint), [Hyperliquid fees](https://hyperliquid.gitbook.io/hyperliquid-docs/trading/fees).
