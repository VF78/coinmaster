# CM-05 #110 — native Sandbox replay feasibility, source-only

Date: 2026-09-26. Pinned Nautilus 1.231; two isolated disposable /tmp probes, no active worker, credentials, real order, service, venv, lockfile, strategy, or approval change.

SandboxExecutionClient.on_data feeds instrument/quote/trade/bar to one native SimulatedExchange, then calls exchange.process(ts_init). Its configuration defaults use_random_ids=false; documented trade IDs are deterministic. The CM-03 subclass uses this native exchange with HyperliquidUsdcFeeModel and explicit model USD/USDC FX. The existing PaperRuntime journal does not contain all ordered public market inputs. The installed worker's open BTC/TP therefore cannot be recovered retroactively by input replay.

Initial probe replayed identical fixed quotes into fresh native TradingNodes via the existing strategy submit path. Native cash and fills matched economically (entry 0.01 @ 60000, 0.27 USDC taker fee; maker TP two 0.005 fills @ 60010, 0.0450075 USDC each; final total/free 9999.739985 USDC, locked zero), but generated client order IDs differed because the strategy OrderFactory uses each node's LiveClock.

A read-only API check found supported OrderFactory.market/limit parameters client_order_id=ClientOrderId(...), and Strategy.submit_order accepts the prebuilt order. One corrected disposable probe used those explicit stable IDs and a 0.03 entry/TP. Fresh native exchanges matched exactly at the chosen replay boundary and after the next tick: both orders had the same client/venue/trade IDs and FILLED status, cash total/free 9999.219955 USDC, locked zero, and identical entry and maker fee/fill records. This proves deterministic native *flat* reconstruction when inputs and order IDs are supplied. It does not prove open-position restart.

The intended partial TP boundary did not stay open: the first 0.005 maker fill at tick 3 was immediately followed by a 0.025 maker fill at that same quote timestamp, despite a 0.005 bid-size fixture. Native order and position were flat before the simulated crash. The requested working TP remaining quantity, open position/account margin parity, next strategy decision, and truncated/corrupt ordered-journal rejection were therefore not proved. The corrected probe submitted test orders with explicit IDs through the public native API; production WaveOverlayStrategy._submit_intent still generates IDs from its live-clock factory, and domain episode IDs are random. No production replay hook or journal was implemented.

Decision: NO-GO for position-preserving Sandbox restart on this evidence. A new version-pinned test must first create a genuinely working partial maker TP using a supported native book/event fixture, then replay exact durable SubmitOrder/cancel commands with original IDs and a checksummed strictly ordered instrument/model-FX/market-input stream into one fresh SimulatedExchange while suppressing duplicate strategy decisions. It must compare native open order, position, account, fill IDs and the next decision, and reject missing/corrupt/truncated input before takeover. This cannot repair the current worker's open BTC/TP without its missing historical input stream; do not restart it or infer flat from a new empty Sandbox cache.

## Durable production replay gate after proof (2026-09-26)

No replay runtime hook was installed. The checked-in test supplies a complete ordered public stream and fixed ClientOrderId values itself; the current worker cannot. Its PaperRuntime schema stores event IDs, durable submit intents, funding rows, a latest snapshot and a strategy checkpoint, but has no lossless, sequence-numbered payload rows for native instruments, Bybit bars or Hyperliquid quote/trade/mark/funding inputs before DataEngine and Sandbox delivery. Public data factories feed the node directly. WaveOverlayState creates episode and intent IDs with uuid4, and WaveOverlayStrategy creates orders through live-clock OrderFactory without explicit client_order_id at entry, TP, cancel/replacement and forced-close submit sites. This prevents verified deterministic command reconstruction from current durable state.

The required next vertical is therefore a coordinated sealed strategy/domain ID change, pre-native input capture, committed-prefix validation, replay suppression of duplicate decisions, and actual crash/repeated-restart/corrupt-prefix acceptance. A partial journal table alone would create a misleading recoverability claim. The exact approved strategy hash remains unchanged, and the installed open BTC/TP remains NO-GO for restart; historical inputs are absent. There is no SIGKILL/repeated restart or corrupt-prefix proof yet.

## Pinned 1.231 dispatch/completion barrier probe (2026-09-26)

The checked-in disposable TradingNode test now captures state immediately after LiveDataEngine.process(first quote) returns. At that point the strategy has not advanced and there is no native fill or position; later native callbacks create the entry, TP and partial fill. This is a direct regression against treating process() return as commit completion. After the full event sequence has visibly settled, asyncio.Queue.join() on the native data queue still times out: the pinned LiveDataEngine._run_data_queue consumes with get() but does not call task_done(). The test does not poll for empty queues.

Source inspection of the pinned wheel shows DataEngine.process/execute, RiskEngine.execute/process and ExecutionEngine.execute/process enqueue into separate async queues and return None. None supplies an input-scoped completion future or a transitive receipt that all downstream strategy, risk, command, Sandbox exchange and fill callbacks have completed. A marker on only the data queue or its emptiness cannot certify the downstream queues. No sound serialized dispatch/completion barrier was established through the supported 1.231 APIs. Implementing a private queue/fork bridge without its own native vertical proof would overstate durability, so no production WAL, ID, startup replay or strategy change was installed. SIGKILL/repeated-restart/corrupt-prefix acceptance remains unproved; the active open worker stays NO-GO for restart.

## Streaming BacktestEngine production boundary check (2026-09-26)

The checked-in `test_hl_backtest_streaming_recovery_probe.py` proves a deliberately supplied QuoteTick/TradeTick stream can rebuild a native open 0.025 BTC position, PARTIALLY_FILLED 0.025-leaves TP, exact client/venue/trade IDs, fills, fees and USDC balances with `BacktestEngine.run(streaming=True)`. Its SQLite chain rejects a mutated row. It does not capture the production public feed, use the sealed decision path with its real IDs, exercise SIGKILL, or establish a reconnect handoff. It also has no end-of-log completeness seal: deletion of the final valid row would leave a shorter valid chain.

The production worker currently builds a `TradingNode` with Bybit and Hyperliquid live data factories. Their data flows directly into LiveDataEngine and then WaveOverlayStrategy and the local Sandbox exchange; `FeedObserver` records only recent quote/mark/funding health, not a lossless ordered decision-input stream. A BacktestEngine cannot receive those adapter subscriptions as a drop-in replacement. A correct one-engine vertical would need one public collector that durably serializes every instrument, Bybit signal/bar, Hyperliquid quote/trade/mark/funding and model FX input before native dispatch, plus an explicit sequence fence/buffer across replay-to-live handoff. It would also need deterministic strategy episode/intent/order IDs and a replay-safe admission gate, while retaining the approved trading rules. None of these supported production boundaries exists in the current host. Reusing the live node as collector while it also executes the strategy would create two native execution engines; moving feeds without a fenced collector risks skipped or duplicated decisions.

Decision: NO-GO for a production host cutover in this focused pass. No production journal or partial host integration was added. Current source HEAD before this documentation checkpoint was `7353c01`; the isolated installed release differs in host, worker and strategy source SHA-256 (source `cdce648f`, `b75a9ee8`, `436d82ec`; installed `6f19664d`, `41ebd6c9`, `f890667e`). `coinmaster-hl-stageg-testnet.service` was active with PID 638008 and zero restarts at inspection. Its present virtual BTC/TP has no historical input journal and remains unrecoverable by retroactive replay. Owner permits its one-time discard only at an eventual verified cutover; planned restarts, feed loss/recovery and abrupt crashes after that cutover require complete native reconstruction. Do not restart or deploy the current service on this evidence.

Focused source tests: 11 passed, 2 failed in 110.57s across the streaming probe, open replay, Stage-G lifecycle, factual reconstruction and money projection files.
